# WUALT incident-report wrapper 0.11.0

The backend supplies one incident JSON record. The model interprets the transcript, keywords and relevant context, then fills **only SLM Interpretation**. All other sections use the supplied record and the boxed report template. The existing button trigger is unchanged; this release does not add a trigger or require every request to contain an SOS. The backend selects the observation window.

## How it works

1. Validate the JSON and timestamp consistency; preserve the normalized input snapshot.
2. Build typed evidence from transcript, derived keywords, activity, chat, recorded events and physiology. Preserve source role, timing, reliability and reference comparability. Contact details, officer fields and supplied follow-up text stay out of the model prompt.
3. Generate one interpretation paragraph with sentence-level source IDs. Full wording, negation and quotations take precedence over isolated keywords. No fixed assessment opening is imposed.
4. Check citations, numbers, attribution, relevant limitations and SOS handling. Allow one bounded revision; a detected factual error cannot be traded for better coverage. These checks are diagnostics, not semantic certification.
5. Insert the paragraph into SLM Interpretation. The template displays supplied measurements, transcript, chat and administrative fields. The wrapper does not dispatch assistance.

This release changes the wrapper, prompts and pretrained model configuration. **It does not train model weights.** The pin is Qwen3-14B Q8_0 with llama.cpp b11582; the weights are about 15.7 GB, with additional memory needed for runtime/context. Exact revision and checksums are in wualt_slm/assets/runtime.lock.json. RunPod is an optional host, not part of the architecture.

## Backend input

Use schema_version **incident-v2**. The complete example is wualt_slm/assets/examples/physiology-v2.json. API endpoints: GET /v1/incident-input-example; the full contract is published in /openapi.json.

- Report fields: request_id, incident_id, report_number, reported_at, incident_start, incident_type, observation_window and wearer, with optional officer, location, assessment, events and follow-up fields.
- audio.transcript: timestamped text with optional speaker labels. audio.transcript_reliability: usable, limited, unreliable or unavailable. audio.keywords: extraction hints from that speech, not independent evidence.
- activity.label: optional label such as walking or running. No detailed movement is inferred.
- chat_context.messages: optional timestamped user/assistant messages. User messages are self-report; assistant questions are not observations. Earlier plans do not establish current actions.
- physiology: HR measurements/reference/quality, optional HRV metric/window/reference comparability, and supported additional measurements. Values alone do not establish emotions, diagnosis or intent.
- button: existing recorded state and timestamp. The supplied incident_start and observation window are retained.
- incident_description and clarification_required: optional backend text for those template fields. Missing text displays "Not supplied." and is never generated by the model.

Legacy incident-v1 records are adapted internally while their original schema and normalized values remain in report.input. Legacy acoustic observations remain explicitly reported observations. New integrations should use incident-v2. Invalid records fail before inference.

## Install and run

From incident_report_slm, using Python 3.11 or later:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
python -m wualt_slm.setup_model --model-only --directory /workspace/slm-runtime
llama-server -m /workspace/slm-runtime/models/Qwen3-14B-Q8_0.gguf --alias wualt-context-slm --host 127.0.0.1 --port 8081 -c 8192 -np 1 -ngl 99 --jinja --reasoning off
```

In another terminal:

```bash
export WUALT_MODEL_URL=http://127.0.0.1:8081
export WUALT_REPORT_MODE=guarded
wualt-slm serve --host 0.0.0.0 --port 8000 --data-dir /workspace/report-data
```

The Docker image runs the wrapper API; provide WUALT_MODEL_URL for a separate model service. Configure WUALT_API_KEY and WUALT_ALLOWED_ORIGINS when exposing the API.

## Generate and review

```bash
wualt-slm generate input.json --require-model --output /workspace/review/report.json --pdf /workspace/review/report.pdf
```

Or POST the JSON to /v1/incident-reports, then download /v1/incident-reports/{id}/pdf. Repeating a request_id with the same payload reuses the saved report; a changed payload under that ID returns 409. Reports and model weights are excluded from Git.

The response has model_sections: ["interpretation"] and fallback_enabled: false. narrative.interpretation contains model text and citations. narrative.description and narrative.clarification contain supplied text or an explicit missing-value label. Chat messages remain source records; their relevant meaning belongs in SLM Interpretation.

Both modes disable fallback. **guarded** rejects flagged output; **raw_review** retains structurally valid model text and flags for manual review. Invalid/truncated output or unavailable inference fails in both modes. The API returns 502 on generation failure and 503 with Retry-After when busy; it never saves a successful-looking substitute.

No diagnostic flags does not prove accuracy. Attribution, quotation, ambiguous negation and physiological meaning still need human review. A recorded SOS retains urgent handling even when an ordinary explanation is possible.

## Verification

```bash
pytest -q
python scripts/evaluate_contextual_reports.py --model-url http://127.0.0.1:8081 --output /workspace/review/context-cases
```

Unit tests use explicit simulated model responses for contracts, errors and rendering. The evaluation command uses live inference and saves reports separately. The old assessment-match rubric in evaluate_interpretations.py is historical and must not be used to score this interpretation-only contract. No test suite claims exhaustive scenario coverage or semantic certification.
